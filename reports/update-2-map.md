## 2. Вкладка «Копилка»

Сверху вниз:

1. **Свинка.** Большая иллюстрация (inline SVG, без картинок-файлов): плоская, округлые линии толщиной как у иконок, цвет — текущий акцент, в тёмной теме свои токены. Внутри свинки уровень заполнения = всё отложенное ÷ сумма целей банок (у подушки без цели — не участвует, см. вопрос 3). При пополнении монетка падает в прорезь, уровень поднимается; при «Забрать» опускается. Под свинкой «В копилке 245 BYN» и «в этом периоде +45 из 110».
2. **Кнопки** «Положить» и «Забрать». Шторка: сумма (клавиатура как у траты), выбор банки, строка последствий: «Лимит станет 24,10 в день». «Положить» — не больше, чем создаст дефицит. «Забрать» — не больше, чем лежит в банке; предупреждение: у цели к дате «Чтобы успеть к 1 марта, в день будет уходить 3,10 вместо 2,80», у процентной «Наполнится позже: ~20 дек вместо 12 дек».
3. **Банки** карточками: название, «80 из 150», прогресс, способ («15% с поступления», «к 1 марта · 2,80 в день», «50 BYN каждую неделю», «вручную»), прогноз «наполнится ~12 дек», вехи 25/50/75 %. Тап — настройка банки. «+ Новая банка».
4. **«Как копим»** — всё, что настраивает откладывание, в одном блоке:
   - раскладка поступления: «10% подушка · 15% наушники · 75% на жизнь», проценты правятся прямо здесь (сумма не больше 99 %);
   - округление трат до 1 BYN: вкл/выкл, в какую банку;
   - что делать с остатком дня: спрашивать утром (как сейчас) или не спрашивать.
5. **История**: «30 сен +45,00 Стипендия → Наушники», «29 сен +8,00 Остаток дня → Подушка», «27 сен −20,00 Забрал из подушки», «+0,70 Округление». Последние 20, «Показать все».

**Банка полна** (накоплено = цель): свинка радуется, конфетти в акцентном цвете, выбор «Купил» (трата из банки, лимит не трогает, как сейчас) или «Коплю дальше» (поднять цель).

## 3. Настройка банки

Одна форма для подушки и целей: название, цель (у подушки необязательна), **способ копить** — один из:

- **к дате** (как сейчас): равномерно до дедлайна;
- **% с каждого поступления** (как сейчас), 1–99 %;
- **сумма по расписанию** (новое, вопрос 4): N BYN каждую неделю (день недели) или каждый месяц (число);
- **вручную** (новое, «просто коплю»): только «Положить», округления и остатки.

Плюс «уже накоплено» при создании. Подушка остаётся особой банкой: всегда первая, её нельзя удалить, «Взять из подушки» превращается в общий «Забрать».

- `savingsMoves[]` (новое): `{ id, goalId | null (null — подушка), amountKopecks (со знаком), date, createdAt, source: 'income' | 'leftover' | 'period' | 'manual' | 'roundup' | 'withdraw' | 'schedule' }`. Это журнал для истории и основа для ручных движений.
- `settings.roundUp: { goalId | null } | null` (шаг всегда 1 BYN).
- `cushion`: без изменения режимов; у подушки появляется необязательная цель `targetKopecks | null` (для свинки и прогресса).
- Миграция v5 → v6: `schedule = null`, `savingsMoves = []`, `roundUp = null`, `cushion.targetKopecks = null`. Копии v4 и v5 импортируются. История у старых данных начинается с дня обновления.

## 5. Расчёт (дополнения, все чистые функции в `src/domain/`)

- **Накоплено к дню x** = как сейчас + Σ ручных движений банки с датой ≤ x. Движение «Положить» или «Забрать» у цели к дате перестраивает план так же, как «Отложить остаток» сейчас (`startDate = сегодня`, `initialSaved = накоплено + X`), поэтому остаток плана распределяется заново.
- **Сумма по расписанию**: накоплено к x = `initialSaved + N × число вхождений с startDate по x`, не больше цели. В контрольной точке `c` учитываются вхождения раньше `c`.
- **Округление**: при добавлении траты `ceil(сумма / шаг) × шаг − сумма` уходит движением `roundup` в выбранную банку. Трата 4,30 при шаге 1 BYN → 0,70. Округление не больше того, что создаст дефицит; отмена траты отменяет и округление.
- **Прогноз «наполнится ~дата»**: процентная — по плановым поступлениям вперёд, по расписанию — по вхождениям, к дате — дедлайн, вручную — не показывается.
- Лимит, дефицит, «Как дотянуть» учитывают новые способы автоматически, потому что всё идёт через «накоплено к дню». Рычаги: для банки по расписанию — сумма −25 %.
- Эталонные числа для тестов добавятся в `PROJECT_MAP.md`, раздел 2 (пример Г).

## 7. Как проверим (e2e)

- Вкладки: Сегодня · Копилка · История · Финансы · Настройки; календарь открывается в «Финансах», «Ближайшее» ведёт туда.
- «Положить 20» в «Наушники»: свинка наполнилась, в истории «+20,00 Вручную → Наушники», лимит упал.
- «Забрать 20» из цели к дате: предупреждение с новой суммой в день, после — лимит вырос.
- Округление 1 BYN: трата 4,30 → в истории «+0,70 Округление», отмена траты убирает обе строки.
- Банка «50 BYN каждую неделю»: в понедельник +50 в истории, лимит учитывает следующие вхождения.
- Банка полна: «Купил» — трата без изменения лимита.
- Старые данные v5 и копия v4 открываются без потерь.

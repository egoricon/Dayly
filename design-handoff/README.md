# Handoff: Финансовый помощник студента (iOS, MVP)

## Overview
Мобильное приложение для студента в Беларуси (валюта BYN). Главный экран отвечает на вопрос «Сколько я могу потратить сегодня, чтобы денег хватило до следующего поступления?». Дневной лимит показан крупно, баланс вторичен.

Согласованный сценарий — **Превью 2 (экраны 2a–2j)** в файле `design/Превью главного экрана.dc.html`. Превью 1 (1a–1f) — ранние варианты для справки; из них взяты типографика цифры (1a) и кольцо (1b).

## About the Design Files
Файлы в `design/` — **дизайн-референсы в HTML**: они показывают внешний вид и поведение, это не продакшн-код. Задача — воссоздать эти экраны в выбранном стеке проекта (React Native / Expo, SwiftUI, PWA и т.п.) по его паттернам. Стек ещё не выбран — выбирайте по плану из PROJECT_MAP.md.

Открыть: `design/Превью главного экрана.dc.html` в браузере (рядом должен лежать `support.js`). Экраны подписаны бейджами `2a`…`2j`.

## Fidelity
**High-fidelity.** Цвета, шрифты, размеры и тексты финальные. Воспроизводить точно; нативные системные элементы (status bar, home indicator, клавиатура) можно брать платформенные.

## Правила расчёта, заложенные в дизайн
- Период — **до следующего поступления** (не календарный месяц). В примере: сегодня 26.09, стипендия 05.10 → 9 дней.
- Дневной лимит = (деньги сейчас − обязательные платежи − резерв на продукты − резерв на транспорт − доля запланированных покупок за период − подушка) ÷ дней до поступления.
  Пример: 586,00 − 95,00 − 150,00 − 30,00 − 38,00 − 30,00 = 243,00 ÷ 9 = **27,00 BYN/день**.
- Траты категорий **«Продукты» и «Транспорт» списываются из резервов** и не уменьшают дневной лимит. Остальные категории — из дневного лимита.
- **Перенос остатка**: недотрата/перерасход распределяется равномерно на оставшиеся дни периода. Завтрашний лимит = (свободно на период − потрачено из лимита) ÷ оставшиеся дни.
- Перерасход за день показывается спокойно (красная сумма со знаком «−» и новый лимит на завтра), без блокировок.
- Запланированные покупки копятся частями (в примере наушники 150 BYN, по 38,00 за период).
- Все деньги — **целые копейки**, формат вывода `27,50 BYN` (запятая, неразрывный узкий пробел для тысяч `1 020,00`), минус — символ `−` (U+2212).

## Interactions & Behavior
- Онбординг: 2a → 2b → 2c → 2d → 2e → 2f. «Пропустить» на 2d = 0 платежей. Назад — свайп/кнопка iOS.
- Шторка 2g: открытие с «+ Трата», стандартная анимация bottom sheet (~300 мс, ease-out), закрытие свайпом вниз или тапом по затемнению.
- Ввод суммы: максимум 5 цифр до запятой и 2 после; повторная запятая игнорируется; ведущий 0 заменяется.
- Кольцо: анимировать изменение дуги ~400 мс ease-out после добавления траты.
- Лимит пересчитывается без перезагрузки; данные хранятся локально и переживают перезапуск.
- Долгий тап/свайп по трате в истории — удаление/редактирование (в макетах не показано).
